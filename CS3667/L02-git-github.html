Git and GitHub

  • Before we write enterprise code, we need to know how to manage it.
  • Historically, version control stored 'deltas' — just the changes between files.
  • Git revolutionized this by taking a snapshot of your entire project at a given point in time.
  • Under the hood, Git bundles your code with meta-data into a 'blob' and assigns it a SHA-1 hash.
  • This ensures integrity—if a single bit changes, the hash changes.
  • Today, we are setting up our tools on the course Linux VM

Evolution of Version Control

  • Local Systems: Manual copying, backup folders (timestamped). Full copies of files.
  • Centralized Systems (CVS, Subversion): Single server maintains deltas. Single point of failure.
  • Distributed Systems (Git, Mercurial): Peer-to-peer. Each peer "fully mirrors" the repository.

Git's Secret Sauce: Snapshots

  • Git uses project “snapshots” not file deltas/diffs.
  • Everything is check-summed using a SHA-1 hash.
  • The SHA-1 hash (40 hex characters) is a unique identifier “key” in the database.
  • Any content deviation (accidental or intentional) is noticeable.
