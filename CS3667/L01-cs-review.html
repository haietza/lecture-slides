Abstraction

  • Simplifying complexity by focusing on what matters and hiding what doesn’t.
  • Real-world Analogy: A refrigerator. You know how to use it without understanding coolant cycles or compressors.
  • Abstraction is a concept that sits at the very heart of computer science.
  • Why do we need it? Because human working memory is limited. Abstraction reduces cognitive load, makes code reusable, and enables massive systems to be built safely.
  • Think about the java.util package. You use ArrayList without worrying about how the underlying array resizes itself.
  • You interact with an interface, not the complex implementation.

Abstraction

  • Computers are built on layered abstractions:
    • Hardware hides electrical details.
    • Operating systems hide hardware details behind files and processes.
    • Programming languages hide machine code.
    • Functions hide implementation behind clean interfaces.

  • Polymorphism means 'many forms'. It is about flexibility.
  • In Java, subtype polymorphism is the most common.
  • Imagine a draw() function. A Circle class and a Square class can both implement it.
  • You can call shape.draw() without knowing the exact shape.
  • Java handles this via 'dynamic dispatch', meaning it does a lookup at runtime to see what the object actually is before calling the method.

Polymorphism

  • A single interface, function, or operation working with different types of data.
  • Subtype Polymorphism (OOP): A parent class reference pointing to a child class object.
  • Dynamic Dispatch: In Java, instance method calls look at the runtime object to decide which method to execute.
  • Example: Animal a = new Dog(); a.foo(); invokes the Dog's method because Java checks the object type at runtime.

  • For encapsulation in OOP, we bundle data and methods together into a class.
  • But encapsulation is often conflated with information hiding. Information hiding is strictly about access control.

Encapsulation & Information Hiding

  • Encapsulation: Enclosing data and operations into a single syntactic unit (e.g., a Java class).
  • Information Hiding: Restricting access to certain class elements from other code elements.
  • When I make a variable private, I am ensuring no other class can change it unexpectedly.
  • Think about a Point class with private x and y. Can a distance(Point p2) method inside the Point class directly access p2.x?
  • Yes! Because private means private to the class definition, not the specific object instance.

Encapsulation & Information Hiding

  • Access Modifiers:
    • private: Only elements in the same class have access.
    • protected: Same class, subclasses, and package access.
    • package (default): Any class in the same package has access.
    • public: Accessible by any class.
Use https://www.w3schools.com/java/java_encapsulation.asp if needed.
  • No Data Integrity: Any other part of the program can write myAccount.balance = 1000000; and instantly make the user a millionaire without a proper deposit.
  • No Validation: Someone could accidentally (or maliciously) write myAccount.balance = -5000;. A bank account should not drop below zero without specific overdraft rules being triggered.
  • No Audit Trail: In a real banking system, every change to a balance needs to be logged (e.g., tracking the time, location, and reason for a deposit). If anyone can change the variable directly, you cannot trigger logging code when the balance changes.
  • Brittle Code: If you later decide to change how the balance is stored (for example, storing it as an integer of cents to avoid floating-point math errors), you will break every piece of code in your entire program that directly accessed the balance variable.

  • As systems grow, we need higher-level organizational structures.
  • Packages map directly to your file system directories.
  • Interfaces act as strict contracts. If your class signs the contract, it must provide the behavior.
  • Abstract classes are similar but more powerful for creating deep hierarchies, like Animal to Dog to a concrete Poodle.
  • You can instantiate a specific object into a broader reference: Animal gigisDog = new Poodle("Rosie");

Packages, Interfaces, & Abstract Classes

  • Packages: Organizational structures grouping related classes (e.g., java.util). Package names connect to project directory names.
  • Interfaces: A behavior contract. Any class implementing an interface is contractually obligated to implement its methods.
  • Abstract Classes vs Interfaces: Abstract classes can define instance fields and implement methods.
    • They act as higher-level abstractions in hierarchies (e.g., Animal < Dog < Poodle).
